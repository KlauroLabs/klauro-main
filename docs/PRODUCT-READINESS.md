# Klauro Product Readiness

This is the execution and evidence contract for taking Klauro's non-UI product to an externally testable beta. It derives from `docs/cas/SPECIFICATION.md`, `docs/SEMANTIC-MODEL.md`, `docs/SPEC-ABSTRACTION-TIERS.md`, `docs/SPEC-COORDINATION-FABRIC-V3.md`, and the owner clarifications recorded below. A requirement is complete only when its listed proof exists and passes against the current product artifact.

## Product premises

1. Klauro is for any software. AI-built software may benefit disproportionately, but it is not the product boundary.
2. CAS is one recursive structure at arbitrary depth. A leaf is source-derived; a parent composes child facts, computes direct-child seams, and re-derives comprehension for its own purpose.
3. Tiers are a dependency contract: Tier 1 index/graph/static ICELOT; Tier 2 framework/architecture/library conventions; Tier 3 comprehension; Tier 4 observed telemetry; Tier 5 Fabric action and collaboration.
4. Comprehension consists of capabilities, flows, steps, and entities. Capabilities represent purpose. Flows represent complete behavior. Steps are human actions with many-to-many code mappings. Entities are the things the system exists to manage, produce, transform, or communicate.
5. ICELOT is Input, Constraints, Effects, Logic, Output, and Telemetry. It applies below capability, changes abstraction at each level, and always retains evidence/provenance. Static declared telemetry is Tier 1; observed runtime telemetry is Tier 4.
6. Terminality is a general relational signal for comprehension. Terminal and proximal-terminal entities, flows, capabilities, and CAS nodes help identify what a system was built for. Supporting prerequisites such as authentication are not mistaken for purpose unless the analyzed system exists to provide authentication.
7. Fabric enables the free flow of concurrent work on any semantic unit, including overlapping work. It uses continuously updated, participant-attributed CAS; detects duplicate/recreated work and conceptual divergence; shares knowledge; never makes collision avoidance or serialization the organizing axis; and drives merge decisions and surprise toward zero.
8. The UI is outside this readiness program except for the contracts it will consume. CAS and APIs must deliver complete relationships without frontend inference.
9. Production code is self-documenting and contains no comments. Modules and functions are small enough to test in isolation, with explicit boundaries and names that explain the behavior.
10. Analysis logic is structural and corpus-general. Production behavior cannot key on a repository, fixture, customer, domain word list, or one scenario. Framework and library intelligence is extensible evidence interpretation; unknown ecosystems degrade honestly rather than falling through a closed vocabulary.
11. Performance is part of correctness. Parsing uses incremental concrete syntax trees or equivalent native parsers where available; graph work uses indexed or near-linear algorithms; repeated derivations are cached by stable fingerprints; every hot path has a measured budget for large repositories.
