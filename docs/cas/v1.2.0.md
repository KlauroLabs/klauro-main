## Summary of Changes

CAS v1.2.0 introduces **multi-perspective support**, enabling analyzers to provide multiple architectural views of the same codebase. This allows for richer, context-specific visualizations and navigation.

## New Features

### 1. Perspectives

A new top-level field `perspectives` has been added to `CASOutput`:

```typescript
interface CASOutput {
  // ... existing fields from v1.1.0 ...

  perspectives?: CASPerspective[]; // NEW in v1.2.0
}

interface CASPerspective {
  id: string;                    // Unique identifier (e.g., "nestjs-flow")
  name: string;                  // Display name (e.g., "Request Flow")
  description: string;           // What this perspective shows
  analyzer_id: string;           // Analyzer that provides this perspective
  type: 'flow' | 'structure' | 'deployment' | 'data' | 'security' | 'custom';

  // Connection rules for this perspective
  connection_rules?: {
    // Defines how components connect in this perspective
    node_connections?: Array<{
      from_type: string;       // Source node type
      to_types: string[];      // Allowed target node types
      edge_type: string;       // Type of edge to create
      conditions?: Record<string, any>;
    }>;

    // Node types visible in this perspective
    visible_node_types?: string[];

    // Edge types used in this perspective
    relevant_edge_types?: string[];
  };

  layout_hints?: {
    style: 'hierarchical' | 'force' | 'circular' | 'grid';
    direction?: 'TB' | 'LR' | 'BT' | 'RL';
    group_by?: string;
  };

  metadata?: Record<string, any>;
}
```

### 2. Perspective-Aware Nodes

Nodes can now specify which perspectives they belong to:

```typescript
interface CASNode {
  // ... existing fields from v1.1.0 ...

  perspectives?: string[];  // NEW: Array of perspective IDs

  metadata?: {
    // ... existing metadata from v1.1.0 ...

    perspective_data?: Record<string, any>; // NEW: Perspective-specific data
  };
}
```

### 3. Perspective-Aware Edges

Edges can specify their relevance to specific perspectives:

```typescript
interface CASEdge {
  // ... existing fields from v1.1.0 ...

  perspectives?: string[];  // NEW: Array of perspective IDs

  metadata?: {
    // ... existing metadata from v1.1.0 ...

    perspective_data?: Record<string, any>; // NEW: Perspective-specific data
  };
}
```

### 4. Enhanced Analyzer Contributions

Analyzers now report which perspectives they provide:

```typescript
interface AnalyzerContribution {
  // ... existing fields from v1.1.0 ...

  provided_perspectives?: string[]; // NEW: Perspective IDs this analyzer provides
}
```

### 5. Index Enhancement

The index can now group nodes by perspective:

```typescript
interface CASIndex {
  // ... existing indices from v1.1.0 ...

  by_perspective?: Record<string, string[]>; // NEW: Node IDs grouped by perspective
}
```

## Implementation Guidelines

### For Analyzer Developers

1. **Declare Perspectives**: Analyzers should declare all perspectives they provide
2. **Tag Nodes/Edges**: Mark nodes and edges with relevant perspective IDs
3. **Define Connection Rules**: Specify how components connect within each perspective
4. **Provide Layout Hints**: Suggest optimal visualization layouts

### For Visualization Tools

1. **Perspective Switcher**: Provide UI to select active perspective(s)
2. **Filter by Perspective**: Show only nodes/edges relevant to selected perspective
3. **Apply Connection Rules**: Use perspective rules to determine valid connections
4. **Respect Layout Hints**: Use suggested layouts for better visualization

## Backward Compatibility

- All v1.1.0 CAS outputs remain valid in v1.2.0
- The `perspectives` field is optional
- Analyzers without perspective support work as a single "default" perspective
- Existing tools can ignore perspective fields and function as before

## Migration Guide

### From v1.1.0 to v1.2.0

1. **Update CAS Version**: Change `cas_version` to "1.2"
2. **Add Perspectives** (optional): Define perspectives for richer views
3. **Tag Nodes/Edges** (optional): Add perspective arrays to relevant items
4. **Define Connection Rules**: Specify how components connect per perspective
