# CAS v1.9.0 RFP: Codebase Idiom Intelligence

## Status

Accepted for implementation.

## Product Problem

CAS already helps agents move faster by resolving targets, relationships, risk, tests, and behavioral invariants without broad file-by-file discovery. The remaining quality gap is repo-local fit: agents can produce a correct patch that still feels foreign to the codebase because it misses local naming, placement, module boundaries, error style, testing style, migration practice, or auth/tenant-scope conventions.

Klauro should help agents make changes that look like they were written by someone who understands the codebase.

## Scope

CAS v1.9.0 adds Codebase Idiom Intelligence:

- `codebase_idioms`
- `idiom_summary`
- `idiom_examples`
- `idiom_violations`

Idioms are evidence-backed repository-local conventions. They are not generic lint rules. They are derived from the actual analyzed graph and then exposed to UI and MCP consumers.

## Idiom Categories

- `naming`
- `file-organization`
- `module-boundary`
- `dependency-injection`
- `data-access`
- `error-handling`
- `validation`
- `auth-tenant-scope`
- `logging`
- `testing`
- `migrations`
- `async-style`
- `configuration`

## Data Structures

```typescript
interface CASCodebaseIdiom {
  id: string;
  category: CASIdiomCategory;
  name: string;
  description: string;
  confidence: number;
  prevalence: number;
  evidence: CASIdiomEvidence[];
  positive_examples: CASIdiomExample[];
  affected_scopes: CASIdiomScope;
  agent_guidance: {
    do: string[];
    avoid: string[];
    validation: string[];
  };
  deviations?: CASIdiomViolation[];
}
```

Each idiom must include confidence, prevalence, evidence, positive examples, affected scopes, agent guidance, and known deviations where detected.

## Analyzer Requirements

The analyzer should run idiom extraction after graph construction, framework enrichment, test extraction, migration detection, behavioral invariant derivation, and analysis-fact generation.

The detector should derive conventions from:

- Nodes and node metadata
- Edges and module/package boundaries
- File paths and source roots
- Imports and decorators
- Tests, fixtures, and mocks
- Migrations and schema files
- Behavioral invariants
- Patterns and deviations
- Configuration and runtime facts
- Analysis facts

## MCP Requirements

The MCP server must expose:

- `get_codebase_idioms`
- `get_idiom_examples`
- `validate_codebase_idioms`
- `get_idiom_aware_work_packet`

`get_agent_work_packet` must include compact `idiom_context` for real work. Modify/debug/review tool plans must include idiom validation after edits alongside behavioral invariant validation.

## Proof Requirements

Add live copied-repo A/B proof:

- Both agents receive the same task.
- The with-Klauro arm receives CAS idiom context.
- The without-Klauro arm cannot use CAS, MCP, or precomputed work packets.
- The evaluator scores correctness, idiom conformance, minimality, test relevance, boundary preservation, and file targeting.
- Acceptance requires no with-Klauro correctness regression and a positive idiom-conformance delta.

Add machine-wide proof:

- Discover every real Git repo under `~/dev`.
- Exclude generated benchmark/live-trial copies, dependency directories, caches, and build artifacts.
- Include nested Git repos when they are real standalone repos.
- Report every repo as passed, failed, unsupported, or skipped with a reason.
- Fail final acceptance when eligible repos are silently omitted.

## Acceptance Criteria

- CAS v1.9.0 outputs idioms on representative NestJS, React, Python, Rust, and mixed repositories.
- MCP tools return compact, evidence-backed, target-filterable idiom context.
- `validate_codebase_idioms` flags non-idiomatic diffs.
- Live idiom benchmark shows positive idiom-conformance delta without correctness regression.
- Machine proof accounts for every discovered repo and verifies analysis, readiness, incremental value, idiom extraction, and live idiom proof.
