# CAS Analyzer Roadmap

## Current foundation

Klauro produces a recursive, evidence-backed CAS graph for human and agent understanding of any software system. The active analyzer covers TypeScript, JavaScript, Python, Java, C#, Dart, Go, Rust, PHP, Kotlin, Ruby, Swift, Scala, and additional registry-backed source shapes. Language, framework, library, architecture, telemetry, comprehension, and Fabric layers feed the same canonical truth model.

Implemented foundations include:

- Full nodes, edges, entry points, exit points, calls, tests, data access, dependencies, deployables, and cross-repository seams.
- Recursive child CAS composition with arbitrary depth, cycle rejection, parent reframing, orphan reporting, and complete child preservation.
- Canonical capabilities, flows, steps, entities, ICELOT, terminality, idioms, invariants, risks, runtime links, and provenance.
- Incremental parsing and invalidation with canonical cold-analysis parity and bounded locality.
- MCP orientation, task planning, coding context, risk, tests, invariants, idioms, proposal previews, telemetry, and Fabric collaboration.
- Hosted analysis, thin-client installation, source filtering, local CAS caching, runtime ingestion, and cross-machine coordination.

## Active non-UI priorities

1. Prove AI-authored capability names and descriptions against authorized providers and varied real repositories without domain hardcoding.
2. Keep language, framework, and library depth open-ended through registries, declarative evidence, and honest unknown-ecosystem degradation.
3. Reduce large-graph persistence, composition, and query costs while preserving complete relationships and deterministic identity.
4. Expand observed telemetry from ingestion and correlation proof into sustained production drift, latency, error, and path-frequency evidence.
5. Exercise Fabric over longer multi-machine workloads and drive merge-decision and surprise rates toward zero without blocking overlap.
6. Run every beta gate against one source-exact candidate, publish its artifacts, deploy the same commit, and retain the reports.

## UI boundary

The designed UI is a sibling surface over CAS and is not part of the current beta-readiness program. It may filter, paginate, and visualize CAS facts; it must not infer relationships, terminality, flows, capabilities, or runtime correlation that belong in CAS.

## Analyzer design rules

1. Register analyzers and source shapes through canonical registries.
2. Detect behavior from syntax, manifests, imports, configuration, decorators, conventions, and graph structure.
3. Enhance canonical facts instead of creating parallel truth models.
4. Preserve analyzer attribution, evidence, confidence, and uncertainty.
5. Emit every relationship downstream surfaces require.
6. Use indexed, incremental, bounded algorithms and measure large-repository budgets.
7. Never key production behavior to a repository, customer, fixture, or closed domain vocabulary.

The authoritative completion contract is `docs/PRODUCT-READINESS.md`; the formal graph contract is `docs/cas/SPECIFICATION.md`.
