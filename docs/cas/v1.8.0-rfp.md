# CAS v1.8.0 RFP: Incremental Analysis

**Version:** 1.8.0
**Status:** Draft
**Author:** Klauro Team
**Date:** 2026-02-05

## Abstract

This RFP proposes incremental analysis support for CAS, enabling efficient re-analysis of codebases by detecting changes and re-analyzing only modified files and their dependents. This dramatically reduces analysis time from 30+ seconds to 2-5 seconds for typical file modifications.

## Motivation

Full CAS analysis is computationally expensive, taking 30-60 seconds for medium-sized codebases. After a developer modifies files, the analysis becomes stale and must be re-run entirely. This creates friction in development workflows, especially when integrated with AI coding assistants that benefit from up-to-date analysis.

### Goals

1. **Fast incremental updates**: 2-5 seconds for single file changes
2. **Accurate change detection**: Multi-tier detection (mtime, git, content hash)
3. **Dependency-aware propagation**: Re-analyze affected files via import graph
4. **Rich change reporting**: Detailed reports of what changed and impact
5. **State persistence**: Track analysis state between runs
6. **Change history**: Queryable history of changes over time

### Non-Goals

1. Real-time watch mode (deferred to v1.9.0)
2. Cross-repository impact analysis (deferred to v1.9.0)
3. AI-specific features like context bundles (deferred to v1.9.0)

## Specification

### 4.12 Incremental Analysis Structures (v1.8.0)

#### IncrementalState

Tracks the state of a previous analysis for change detection:

```typescript
interface IncrementalState {
  version: string;                              // State schema version
  projectPath: string;                          // Analyzed project path
  lastFullAnalysis: string;                     // ISO 8601 timestamp
  lastAnalysisTimestamp: number;                // Unix ms for mtime comparison
  gitCommitHash?: string;                       // Git commit at last analysis
  files: Record<string, FileAnalysisRecord>;    // Per-file tracking
  analyzerVersions: Record<string, string>;     // Analyzer versions used
  config?: {
    rebuildThreshold?: number;                  // % changed files to trigger full rebuild
    watchDebounceMs?: number;                   // Debounce for watch mode
    maxPropagationDepth?: number;               // Max depth for dependency propagation
  };
}
```

#### FileAnalysisRecord

Tracks analysis state for a single file:

```typescript
interface FileAnalysisRecord {
  filePath: string;                   // Relative path from project root
  contentHash: string;                // SHA256 hash of file content
  mtimeMs: number;                    // File mtime at analysis time
  lastAnalyzed: string;               // ISO 8601 timestamp
  analyzerId: string;                 // Primary analyzer used
  nodeIds: string[];                  // Node IDs created from this file
  edgeIds: string[];                  // Edge IDs created from this file
  entryPointIds: string[];            // Entry points from this file
  exitPointIds: string[];             // Exit points from this file
  importedFiles: string[];            // Files this file imports (dependencies)
  exportedSymbols: string[];          // Symbols this file exports
}
```

#### FileAnalysisResult

Result of analyzing a single file (returned by analyzers):

```typescript
interface FileAnalysisResult {
  filePath: string;                   // Relative path
  contentHash: string;                // Content hash
  mtimeMs: number;                    // File mtime
  nodes: CASNode[];                   // Nodes extracted
  edges: CASEdge[];                   // Edges extracted
  entryPoints: CASEntryPoint[];       // Entry points found
  exitPoints: CASExitPoint[];         // Exit points found
  imports: string[];                  // Import paths (for dependency tracking)
  exports: string[];                  // Exported symbol names
}
```

#### ChangeSet

Represents detected changes between analysis runs:

```typescript
interface ChangeSet {
  added: string[];                    // New files
  modified: string[];                 // Changed files
  deleted: string[];                  // Removed files
  affectedFiles: string[];            // Files affected via dependencies
  affectedNodeIds: Set<string>;       // Node IDs that need updating
  requiresFullRebuild: boolean;       // True if too many changes
  reason?: string;                    // Why full rebuild needed
  detectionMethod: 'mtime' | 'git' | 'hash';  // How changes were detected
}
```

#### ChangeReport

Detailed report of what changed between analyses:

```typescript
interface ChangeReport {
  timestamp: string;                  // ISO 8601
  previousAnalysis: string;           // Timestamp of baseline
  currentAnalysis: string;            // Timestamp of new analysis

  summary: {
    filesAdded: number;
    filesModified: number;
    filesDeleted: number;
    nodesAdded: number;
    nodesModified: number;
    nodesDeleted: number;
    edgesAdded: number;
    edgesModified: number;
    edgesDeleted: number;
  };

  impact: ImpactAnalysis;

  details: {
    addedNodes: Array<{ id: string; name: string; type: string; file: string }>;
    modifiedNodes: Array<{ id: string; name: string; changes: string[] }>;
    deletedNodes: Array<{ id: string; name: string; type: string }>;
    addedEdges: Array<{ source: string; target: string; type: string }>;
    deletedEdges: Array<{ source: string; target: string; type: string }>;
  };

  changeHistory?: ChangeHistoryEntry[];
}
```

#### ChangeHistoryEntry

Historical record of a change set:

```typescript
interface ChangeHistoryEntry {
  id: string;                         // Unique change ID
  timestamp: string;                  // ISO 8601
  gitCommitHash?: string;             // Associated commit
  gitCommitMessage?: string;          // Commit message
  author?: string;                    // Author from git
  source: 'human' | 'ai' | 'automated' | 'unknown';
  aiSessionId?: string;               // If AI, which session
  aiProvider?: string;                // claude, copilot, cursor, etc.

  changes: {
    files: FileChange[];
    nodes: NodeChange[];
    edges: EdgeChange[];
    entryPoints: EntryPointChange[];
    exitPoints: ExitPointChange[];
  };

  semanticSummary?: string;           // Human-readable summary
  intent: ChangeIntent;               // Inferred intent
  impact: ImpactAnalysis;             // Impact assessment
  suggestedActions: SuggestedAction[];
  breakingChanges: BreakingChange[];
  minimumTestSet: string[];           // Test IDs to run
}
```

### Full Rebuild Triggers

The system MUST trigger a full rebuild when:

1. **>50% of files changed** (configurable via `rebuildThreshold`)
2. **Core config files changed**: package.json, tsconfig.json, angular.json, pyproject.toml, Cargo.toml
3. **Analyzer version mismatch**: `state.analyzerVersions[id] !== currentAnalyzerVersion`
4. **State corrupted/missing**: Invalid JSON, missing files
5. **New framework/language detected**: Project structure changed

### Semantic Rules (v1.8.0)

#### 5.23 Incremental State Management

- `IncrementalState.version` MUST be checked before use; mismatches trigger full rebuild
- `FileAnalysisRecord.contentHash` MUST use SHA256 truncated to 16 characters
- `FileAnalysisRecord.importedFiles` MUST contain relative paths from project root
- `ChangeSet.affectedFiles` MUST include transitive dependents up to `maxPropagationDepth`

#### 5.24 Change Detection

- Change detection MUST follow tier priority: mtime (fastest) -> git -> hash (fallback)
- Git detection MUST include both committed and uncommitted changes
- When git unavailable, MUST fall back to content hash comparison
- `ChangeSet.detectionMethod` MUST indicate which tier was used

#### 5.25 Dependency Propagation

- When file A changes, files importing A MUST be marked as affected
- Dependency graph MUST be built from `FileAnalysisRecord.importedFiles`
- Circular dependencies MUST be handled (track visited set during BFS)
- Propagation MUST stop at `maxPropagationDepth` (default: 5)

#### 5.26 Change History

- `ChangeHistoryEntry.id` MUST be unique across all entries
- History MUST be capped at 1000 entries (oldest pruned)
- `ChangeHistoryEntry.source` SHOULD be inferred from commit message patterns:
  - "Co-Authored-By: Claude" -> `source: 'ai'`
  - "Generated by" -> `source: 'automated'`
- `ChangeIntent.confidence` MUST be based on evidence strength

#### 5.27 Impact Analysis

- `ImpactAnalysis.riskLevel` MUST consider:
  - Number of affected entry points
  - Whether critical paths affected
  - Test coverage of changed code
  - Stability metrics of changed code
- `riskLevel: 'critical'` MUST be assigned when security-sensitive code affected without tests

### Migration Guide

#### Upgrading from v1.7.0 to v1.8.0

**Required changes:**
- Update `cas_version` to "1.8.0"

**Optional enhancements:**
- Implement incremental analysis in analyzers via `analyzeFileSingle()`
- Track `IncrementalState` between analysis runs
- Generate `ChangeReport` for each incremental analysis
- Store `ChangeHistoryEntry` records for change queries

**New analyzer interface:**
```typescript
interface BaseAnalyzer {
  // Existing methods...
```

**Breaking changes:**
- None. All new fields and features are optional.

## Implementation Notes

### Change Detection Tiers

1. **Tier 1: mtime** (fastest)
   - Quick scan of file modification times
   - Skip files with mtime <= lastAnalysisTimestamp

2. **Tier 2: git** (fast + accurate)
   - `git diff --name-only {previousCommit}..HEAD` for committed changes
   - `git status --porcelain` for uncommitted changes
   - Handles staged, unstaged, and untracked files

3. **Tier 3: hash** (fallback)
   - Compare SHA256 hash of file content
   - Used when git unavailable or unreliable

### Performance Targets

| Scenario | Full Analysis | Incremental |
|----------|--------------|-------------|
| Single file change | 30-60s | 2-5s |
| 5-10 files changed | 30-60s | 5-15s |
| New dependency added | 30-60s | 10-20s |
| Large refactor (>50%) | 30-60s | 30-60s (full) |
